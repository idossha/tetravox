# @tetravox/module-sdk

Host API **{{HOST_API}}**, emitted from Tetravox **{{CORE_VERSION}}** (`{{SDK_VERSION}}`).

Everything a Tetravox module is written against: the `ModuleHost` surface, the manifest contract, the
type-only slice of the engine a module may name, the shared contacts kit, and one runtime shim.
Generated by `scripts/emit-module-sdk.mjs` in the Tetravox repository — never hand-edited, never
published to npm.

## Install

Pin the release asset by URL. There is no npm package: an SDK belongs to one core release, and a URL
says which.

```json
{
  "devDependencies": {
    "@tetravox/module-sdk": "https://github.com/idossha/tetravox/releases/download/v{{CORE_VERSION}}/{{ASSET}}"
  }
}
```

## The one rule: your bundle must have no imports

A module is downloaded and loaded as **one ESM file** over `tetravox://module/<id>/<version>/index.js`.
Nothing resolves bare specifiers there — no import map, no `node_modules`, and the app's CSP grants
script execution to that host and to nothing else. So:

- **do not** mark `@tetravox/module-sdk` external in your bundler; let it be **inlined**;
- `import` React, `ModuleHostError`, `stemOf` and the contacts kit **from this package**, never from
  `react` or from a relative copy;
- assert it in CI. Five lines is enough:

```js
import { readFileSync } from 'node:fs';
const src = readFileSync('dist/index.js', 'utf8');
const bad = src.match(/^\s*(?:import\b.*|export\b.*\bfrom\b.*)$/gm) ?? [];
if (bad.length > 0) throw new Error(`dist/index.js must have no imports:\n${bad.join('\n')}`);
```

A rollup config that satisfies it:

```js
export default {
  input: 'src/index.ts',
  output: { file: 'dist/index.js', format: 'es', sourcemap: false },
  external: [], // nothing is external — the SDK shim is inlined
};
```

## What you import

```ts
import type {
  ModuleActivate,
  ModuleHost,
  ModuleInstance,
  ModuleManifest,
  ExtensionBlock,
  Layer,
  PointsLayer,
  vec3,
  vec4,
  Contact,
  ContactSet,
} from '@tetravox/module-sdk';

import {
  MODULE_HOST_VERSION,
  ModuleHostError,
  contacts,
  createElement,
  react,
  stemOf,
  useCallback,
  useEffect,
  useMemo,
  useRef,
  useState,
  useSyncExternalStore,
} from '@tetravox/module-sdk';
```

| What | Where it comes from |
| --- | --- |
| `ModuleHost`, `ModuleInstance`, `ModuleActivate`, `ExtensionBlock`, `ModuleHostError` | `renderer/src/modules/host.ts` — **frozen** at `MODULE_HOST_VERSION` |
| `ModuleManifest`, `ModuleId`, `ModuleKey`, `ArgType`, `stemOf`, `MODULE_HOST_VERSION` | `src/modules/manifest-types.ts` |
| `Layer`, `PointsLayer`, `Dataset`, `vec3`, `vec4`, `Threshold`, `ProbeResult`, `CoordSpaceRef`, `PointToolSpec`, `PointSelection`, `PointToolEvent`, … | the type-only engine subset. Your module **never calls** the engine; everything it can do goes through `ModuleHost` |
| `contacts.*` | the shared contacts kit (`parseTable`, `writeTable`, `buildEditlog`, `fitLine`, `snapContacts`, `paletteColor`, …) |
| `react`, `createElement`, the hooks | the **app's** React. There is exactly one copy, and importing `react` directly would give you a second one and an "invalid hook call" the first time your panel renders |

## Your manifest

`manifest.json` in your release is byte-for-byte a `ModuleManifest` and nothing more — entry file
names, sizes and hashes belong to the release, not to a module's self-description. Generate it from a
typed `src/manifest.ts` so the type is what is checked:

```ts
import type { ModuleManifest } from '@tetravox/module-sdk';

export const manifest: ModuleManifest = {
  id: 'vendor.name',
  title: 'Human name',
  version: '1.0.0',
  hostApi: {{HOST_API}},
  docs: 'https://…', // an external module documents itself at a URL
  activation: ['onToggle'],
  commands: [{ id: 'save', title: 'Save', key: 's' }],
};
```

If this SDK carries `manifest-schema.mjs`, your CI can validate the emitted JSON with node and no
install:

```sh
node -e "import('@tetravox/module-sdk/manifest-schema.mjs').then(async (m) => {
  const r = m.validateManifest(JSON.parse(require('fs').readFileSync('dist/manifest.json','utf8')));
  if (!r.ok) { console.error(r.errors.join('\n')); process.exit(1); }
})"
```

## Releasing a module

Name each asset by its own sha256 — the store layout the app already uses for sample data, and what
lets a download be verified against its own URL:

```sh
for f in dist/index.js dist/manifest.json; do
  sha="$(shasum -a 256 "$f" | cut -d' ' -f1)"
  cp "$f" "/tmp/$sha" && gh release upload "$TAG" "/tmp/$sha"
done
```

Then print the `modules.lock` fragment for the Tetravox repository (bundled modules only) and the
registry `versions[]` entry for `idossha/tetravox-extensions`. Both carry the same hashes, and the
app refuses any file whose bytes do not match.

## Version compatibility

`MODULE_HOST_VERSION` is an integer. The host refuses to activate a module whose manifest `hostApi`
is not the one it implements, rather than running it against a surface that no longer means what it
said. Host changes are additive: a module built against host API {{HOST_API}} keeps working across
core releases until that integer moves.
