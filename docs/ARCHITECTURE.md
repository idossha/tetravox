# Tetravox — Architecture Contract

> High-performance desktop viewer for **voxel volumes** (NIfTI) and **finite-element / surface meshes**
> (Gmsh `.msh`, GIfTI, FreeSurfer, STL/PLY/OBJ) with a linked **3D view + sagittal/axial/coronal 2D slices**.
> Inspired by Freeview (slices, layers, linked cursor), NiiVue (WebGL slicing, colormaps), Gmsh (tetrahedral
> cut planes with per-element colour, element isolation) and MeshLab (mesh inspection). macOS + Linux.

This file is the **contract** every implementation agent builds against. If you need to deviate, change
this file in the same commit and say why in `docs/DECISIONS.md`.

---

## 1. Stack decisions (settled)

| Concern | Decision | Why (short) |
|---|---|---|
| Shell / packaging | **Electron** (electron-vite, electron-builder → `.dmg`, `.AppImage`, `.deb`) | Ships Chromium ⇒ identical WebGL2 on macOS/Linux. Tauri's WebKitGTK on Linux has unreliable WebGL2 and no WebGPU. |
| Rendering | **Custom WebGL2 engine in TypeScript** (`packages/engine`), no three.js, no NiiVue | Our primitive set is small and specialised (3D-texture slices with N composited layers, tet-mesh clip + caps, ID picking). One context/one depth buffer for volumes *and* meshes is a hard requirement; NiiVue cannot host our tet renderer, three.js fights integer/3D textures and churns APIs. WebGPU is a later backend behind the `GpuBackend` boundary, not a v1 goal. |
| Heavy compute | **Rust → WASM** (`crates/`), run in a dedicated **Web Worker** | Parsing 250 MB `.msh`, face hashing of 5 M tets, plane cuts, marching cubes, isolation masks. Pure-Rust crates (no wasm-specific code) so the same code can later be built as a native N-API module or CLI. |
| UI | **React 18 + TypeScript + Tailwind**; small Zustand store | Matches the maintainer's other Electron app. UI is chrome only — all rendering is imperative in the engine. |
| Math | `gl-matrix` | Small, fast, standard. |
| Tests | `cargo test` · `vitest` · Playwright (Chromium headless **and** Electron) with pixel assertions | Rendering must be verified by screenshots, not by "it compiled". |

Non-goals for v1: WebGPU, Windows, DICOM, 4D time-series playback (loading a 4D NIfTI and picking a volume index is in scope), remote/URL loading, plugins.

## 3. Coordinate conventions

* **World space = scanner RAS millimetres.** Everything renders in world space.
* Volumes carry `affine: mat4` (voxel index `(i,j,k,1)` → world). Source: NIfTI sform if `sform_code>0`,
  else qform if `qform_code>0`, else `diag(pixdim)`. Voxel centres are at integer indices.
* Gmsh/SimNIBS meshes are already in the subject's world mm (same space as the m2m `T1.nii.gz`); loaded as-is.
  FreeSurfer surfaces are in *tkr-RAS*; when a companion volume is known apply `vox2ras · inv(vox2ras-tkr)`,
  otherwise load as-is and expose a per-dataset `transform: mat4` the user can edit.
* 2D views: **axial** shows the world XY plane (Z = slice), **coronal** XZ (Y = slice), **sagittal** YZ (X = slice).
  Default display convention is **neurological** (subject left on screen left) with a global radiological toggle.
  Oblique slices (arbitrary plane) are supported by the same shader path; the three canonical views are just fixed planes.
* Cursor = one world point shared by all views. Changing it moves all three slice planes and the 3D crosshair.

## 4. Data model (engine, TypeScript)

```ts
type DatasetId = string; type LayerId = string;

interface VolumeDataset {           // immutable after load
  kind: 'volume'; id; name; path?;
  dims: [nx, ny, nz]; nvols: number; affine: mat4; inverseAffine: mat4; spacing: vec3;
  dtype: 'u8'|'i16'|'u16'|'i32'|'u32'|'f32'|'rgb';   // on-disk type after scl_slope/inter folding rules (§6.1)
  data: TypedArray;                   // nx*ny*nz*nvols (i fastest), scaled to physical units unless labels
  isLabel: boolean;                   // integer type & (intent label | few unique values | LUT file next to it)
  stats: { min, max, mean, p: Record<'1'|'2'|'5'|'50'|'95'|'98'|'99', number>, histogram: Float32Array(256), uniqueLabels?: Uint32Array };
  gpu: { format: 'R8'|'R16UI'|'R32F'|'RGBA8'; texture: WebGLTexture };  // one 3D texture per volume (per selected 4D index)
}

interface MeshDataset {
  kind: 'mesh'; id; name; path?; transform: mat4;
  nodes: Float32Array;                // xyz interleaved, world mm
  tets?: Uint32Array; tetTags?: Int32Array;      // 4 indices per tet, physical tag (SimNIBS 1..10 tissues, 1xxx surfaces)
  tris?: Uint32Array; triTags?: Int32Array;
  nodeFields: Field[]; elmFields: Field[];       // Field { name, ncomp: 1|3|9, data: Float32Array, stats }
  tags: { id: number; name?: string; color: vec4; count: number }[];
  // Everything below lives in the compute worker (WASM) and is referenced by handle:
  handle: number;
}
```

`Layer` = a *visual* binding of a dataset with display parameters. Layers are ordered (bottom→top) and appear
in every view unless per-view visibility is toggled.

```ts
interface VolumeLayer   { kind:'volume'; dataset; visible; opacity; volumeIndex; colormap; window:[lo,hi];
                          threshold:{lo,hi,symmetric:boolean, mode:'hide'|'clamp'}; interpolation:'linear'|'nearest';
                          labelLut?: LabelLut; labelMode:'fill'|'outline'|'both'; outlineWidthPx; showIn3D:boolean /* slice planes drawn in 3D */ }
interface MeshLayer     { kind:'mesh'; dataset; visible; opacity;
                          colorMode:'tag'|'field'|'solid'; solidColor; field?:{source:'node'|'elm', name, component:'mag'|0|1|2}; colormap; window; threshold;
                          tagVisibility: Record<tag, boolean>; edges:boolean; edgeColor; flatShading:boolean; backfaceCull:boolean;
                          clip: { planes: ClipPlane[]; caps:boolean; capColorMode:'inherit'|'tag' };   // ClipPlane { normal:vec3, offset:number, enabled }
                          isolate?: { tags?: number[]; field?:{source,name,component,lo,hi}; sphere?:{center,radius}; box?; labelVolume?:{datasetId, labels:number[]} };
                          contoursIn2D:boolean; contourWidthPx; fillIn2D:boolean /* draw cut polygons on 2D slices */ }
interface IsosurfaceLayer { kind:'iso'; source:{datasetId, field?}; iso:number; color; opacity; smooth:boolean }  // derived surface (marching cubes / tets)
interface AnnotationLayer { kind:'points'|'lines'; ... }  // electrodes, ROI spheres, measurements (v1: points + spheres only)
```

`Scene` = `{ datasets, layers, views: ViewLayout, cursor: vec3, radiological, background, lighting }`
and is JSON-serialisable (`ViewSpec`) so a scene can be saved, reloaded, and rendered headlessly.

## 5. Process / thread architecture

```
┌────────────── Electron main ──────────────┐
│ file dialogs · fs read (+native gunzip)   │  ipc: openFile(path) → ArrayBuffer (transfer)
│ menu · window · packaging · CLI args      │
└───────────────────┬───────────────────────┘
                    │ contextBridge (preload)
┌───────────────────▼───────────────────────┐   postMessage (transferables)  ┌──────────── compute worker ────────────┐
│ Renderer process (UI thread)              │◄─────────────────────────────►│ @tetravox/wasm  (tvx-wasm in WASM)     │
│ React chrome  ·  @tetravox/engine (WebGL2)│  loadVolume/loadMesh → GPU     │ owns parsed datasets by handle          │
│ holds GPU-ready arrays + volume data      │  cut(plane)/isolate/iso → arrays│ topology, cuts, masks, marching, stats  │
│ (for value probes)                        │  latest-wins request ids       │ single-threaded v1; rayon-ready         │
└───────────────────────────────────────────┘                                └─────────────────────────────────────────┘
```

* The UI thread never parses or runs geometry. Every compute request carries a request id; the client keeps only
  the newest pending request per (layer, op) and drops stale results (**latest-wins**), so dragging a cut plane never queues.
* Results are copied out of WASM memory into fresh `ArrayBuffer`s and **transferred** (zero-copy) to the UI thread.
* Volumes: parsed in the worker, transferred to the UI thread (texture upload + probing); the worker keeps a copy only
  while needed (marching cubes, label-volume isolation) — it can re-request from the UI thread.
* Gzip: Electron main gunzips with Node zlib (native) before sending bytes; the WASM readers *also* detect the
  `1f 8b` magic and inflate (miniz_oxide) so the engine works in a plain browser.

## 6. Rust crates — public API contract

Common types (`tvx-core`):
```rust
pub struct Plane { pub normal: [f32;3], pub offset: f32 }      // keep side: normal·x + offset >= 0
pub struct BitMask(Vec<u64>);                                   // per-tet visibility
pub struct Field { pub name: String, pub ncomp: usize, pub data: Vec<f32> }   // n * ncomp, row-major
#[derive(thiserror::Error)] pub enum Error { Parse(String), Unsupported(String), Io(...) }
```

### 6.1 `tvx-nifti`
```rust
pub fn read_nifti(bytes: &[u8]) -> Result<Volume>   // NIfTI-1 (348) and NIfTI-2 (540), .nii and .nii.gz (magic sniff), little/big endian
pub struct Volume { dims:[usize;3], nvols:usize, affine:[[f64;4];4], spacing:[f64;3], datatype:DataType,
                    data:VolumeData /* U8|I16|U16|I32|U32|F32|F64|RGB24|RGBA32 */, scl_slope:f32, scl_inter:f32,
                    cal_min:f32, cal_max:f32, intent_code:i16, intent_name:String, descrip:String, is_label:bool,
                    xyz_units:Units, header_json:String /* every raw header field for the UI "header" panel */ }
impl Volume { pub fn stats(&self, vol:usize) -> VolumeStats;  pub fn gpu_payload(&self, vol:usize) -> GpuPayload /* {format, bytes, scale, offset} */ }
```
Rules: apply `scl_slope/scl_inter` when slope ∉ {0,1} or inter ≠ 0 → F32. Datatypes: uint8, int16, int32, float32,
float64 (→f32), int8, uint16, uint32, RGB24, RGBA32; reject complex/int64 with `Unsupported`. `is_label` heuristic:
integer dtype ∧ (intent_code == 1002 ∨ ≤ 4096 unique values ∧ all integral ∧ min ≥ 0). Stats: min/max/mean, percentiles
1,2,5,50,95,98,99 (sampled histogram OK), 256-bin histogram, unique labels when `is_label`.

### 6.2 `tvx-mesh-io`
```rust
pub fn read_msh(bytes:&[u8]) -> Result<Mesh>          // Gmsh 2.x ascii+binary (SimNIBS default = "2.2 1 8"), 4.1 ascii+binary; $Nodes/$Elements/$NodeData/$ElementData/$PhysicalNames; ignores $Periodic/$Entities beyond what's needed
pub fn read_gifti(bytes) -> Result<Mesh>               // .surf.gii (pointset+triangle, transforms) and .func/.shape/.label.gii → node Field(s)
pub fn read_fs_surface(bytes) -> Result<Mesh>          // triangle file magic 0xFFFFFE (big-endian) + quad file
pub fn read_fs_curv(bytes) -> Result<Field>            // new-format curv (magic 0xFFFFFF)
pub fn read_fs_annot(bytes) -> Result<(Field /*label ids*/, LabelTable)>
pub fn read_stl(bytes) / read_ply(bytes) / read_obj(bytes) -> Result<Mesh>
pub struct Mesh { nodes:Vec<[f32;3]>, tets:Vec<[u32;4]>, tet_tags:Vec<i32>, tris:Vec<[u32;3]>, tri_tags:Vec<i32>,
                  node_fields:Vec<Field>, elm_fields:Vec<ElmField> /* {tri:Field, tet:Field} split by element kind */,
                  physical_names:Vec<(i32,String)>, gmsh_node_numbers:Option<Vec<u64>> }
```
Rules: Gmsh element numbering is 1-based and may be non-contiguous → remap nodes to 0..n and keep the original
numbers. Only element types 2 (tri3) and 4 (tet4) are kept in v1; other types are counted and reported in a
`skipped: Vec<(elem_type,count)>` field, not an error. `$ElementData` is given in file element order (SimNIBS writes
tris first, then tets) → split into per-kind vectors. Vector fields keep `ncomp=3`; tensors 9.
Performance target: `ernie.msh` (176 MB binary, 847 k nodes, 5.9 M elements) parses in **< 1.5 s** native, **< 3 s** WASM.

### 6.3 `tvx-geom`
```rust
pub struct TetTopology { faces:Vec<[u32;3]> /* unique, canonical vertex order */, face_tets:Vec<[i32;2]>, tet_faces:Vec<[u32;4]> }
pub fn build_topology(tets:&[[u32;4]]) -> TetTopology                       // sort-based (radix on packed keys), not HashMap; ernie < 1.5 s WASM
pub fn boundary_faces(topo, mask:&BitMask, tets, nodes) -> Faces            // faces with exactly one visible adjacent tet; outward-oriented; Faces { indices:Vec<u32>, owner_tet:Vec<u32> }
pub fn tag_surfaces(mesh, topo) -> Vec<(tag, Faces)>                        // per-tissue boundary (the default 3D look)
pub fn plane_cut(mesh, topo, plane:&Plane, mask:&BitMask) -> Cut            // Cut { positions:Vec<f32> (3/vertex, de-indexed tris), owner_tet:Vec<u32> (1/tri), tag:Vec<i32> (1/tri), bary_node:Vec<[u32;2]>+t for node-field interpolation, edge_segments:Vec<f32> (polygon outlines for "element edges"), boundary_segments:Vec<f32> (tag-boundary contour lines) }
pub fn isolate(mesh, crit:&IsolateCriteria) -> BitMask                      // tags ∧ field range ∧ sphere ∧ box ∧ label-volume(centroid sample via affine)
pub fn marching_cubes(vol:&Volume, iso:f32, vol_index) -> Surface           // Surface { positions, normals, indices }; in world space via affine; handles label volumes (iso = label ± 0.5)
pub fn marching_tets(mesh, node_field:&[f32], iso:f32, mask) -> Surface
pub fn elm_to_node(mesh, field) -> Field  /* volume-weighted mean of adjacent tets */   pub fn node_to_elm(mesh, field) -> Field
pub fn surface_contours(nodes, tris, plane) -> Vec<f32>                      // segments (x0y0z0 x1y1z1 …) for surface-on-slice outlines
pub fn locate_point(mesh, grid:&PointLocator, p:[f32;3]) -> Option<u32>      // uniform-grid accelerated tet containing p (for probes)
pub fn vertex_normals(nodes, tris) -> Vec<f32>   pub fn face_normals(...)
```
Determinism: same input → byte-identical output (needed for golden tests). No `HashMap` iteration order in outputs.

### 6.4 `tvx-wasm` (worker-side API, handle based)
```ts
load_volume(bytes: Uint8Array) -> { handle, meta(JSON), data: Float32Array|Uint8Array|Uint16Array (view) }
load_mesh(bytes, format: 'auto'|'msh'|'gii'|'fs'|'stl'|'ply'|'obj') -> { handle, meta(JSON incl. tags/fields/skipped), nodes, tets, tris, tags… }
mesh_tag_surfaces(handle) -> per tag {indices, owner_tet}     mesh_boundary(handle, maskId)
mesh_cut(handle, plane, maskId?) -> Cut arrays                mesh_isolate(handle, criteriaJSON) -> maskId
mesh_field(handle, source, name) -> Float32Array              mesh_elm_to_node(handle, name)
mesh_locate(handle, xyz) -> tet index | -1                    volume_marching_cubes(handle, iso)   mesh_marching_tets(...)
surface_contours(handle, plane) -> Float32Array               free(handle)
```
Each call returns views into WASM memory; the TS worker glue (`packages/wasm/src/compute-worker.ts`) copies into
transferable buffers and posts them. `compute-client.ts` exposes a typed Promise API with cancellation/latest-wins.

## 7. Engine (WebGL2) — rendering contract

### 7.1 GL kit (`packages/engine/src/gl/`)
Thin wrappers: `Program` (compile/link, uniform cache, `#include`-style shader chunks), `Buffer`, `VertexArray`,
`Texture2D/3D` (R8, R16UI, R32F, RGBA8; `UNPACK_ALIGNMENT` handled), `Framebuffer` (colour + depth, MRT-ready),
`Timer` (EXT_disjoint_timer_query_webgl2 when available). Single shared context per engine; **no per-frame allocations**.

### 7.2 Passes per frame (per view)
1. **Opaque**: volume base slices (2D views: the slice; 3D: the three planes if `showIn3D`), opaque meshes, cut caps.
2. **Transparent**: layers with `opacity < 1`, sorted by layer order then back-to-front per object, depth-test on / depth-write off.
   (Weighted-blended OIT is a Phase-3 upgrade behind the same pass.)
3. **Overlay**: crosshair, cut-plane gizmo, contours on slices, annotations, orientation cube, scale bar.
4. **Pick pass (on demand)**: same geometry into an RGBA8/`RGBA32UI` FBO encoding `(layer, primitive)` → `readPixels(1×1)`.
Render only on demand (`requestRender()` after any state change) — never a free-running loop. Target ≤ 8 ms/frame at 2×DPR for the full ernie scene on Apple M-series.

### 7.3 Volume slice shader
Slice = a quad in world space (plane through cursor). Fragment: `voxel = inverseAffine * world`, `texcoord = (voxel+0.5)/dims`;
`sampler3D` (trilinear) for scalars, `usampler3D` (nearest) for labels; window/threshold/colormap via a 256×1 RGBA LUT
texture; `discard` outside [0,1]³ and below threshold; symmetric thresholds for signed maps (`|v|` ≥ lo).
Label outlines: compare the label at ±1 *screen pixel* along the two in-plane axes (using `dFdx/dFdy` of the world
position) → outline colour with configurable width; `fill` mode blends the LUT colour with layer opacity.
One quad draw per (layer, plane); overlays use `depthFunc(LEQUAL)` + no depth write so they sit on the base slice.

### 7.4 Mesh shaders
* Attributes: `position`, `normal`, plus either `scalar` (node field, smooth) or per-face flat scalar (de-indexed
  geometry with `flat out`), and `tag`. Colour resolved in the fragment shader through the LUT/window uniforms so
  changing window/colormap costs zero uploads.
* Clipping: up to **6** planes as `vec4` uniforms; `discard` on the clipped side. Caps come from `plane_cut` geometry
  (exact per-element polygons), drawn with the same material (`capColorMode`), plus optional edge lines.
* Element edges: barycentric-coordinate wireframe in the fragment shader (no extra draw call).
* Lighting: headlight Blinn-Phong with configurable ambient; flat shading optional; two-sided lighting.
* Surfaces on 2D slices: `surface_contours` line segments (world space) drawn in the overlay pass; tet cut polygons
  drawn in the opaque pass with tag/field colour when `fillIn2D`.

### 7.5 Views & interaction
Layouts: `1x1`, `1x3` (one large + three), `2x2`, `3d-only`. Every view has its own camera; 2D cameras are orthographic
with fixed orientation (pan/zoom only). 3D camera: orbit (arcball) / pan / dolly, `fit()` to scene bounds, presets
(A/P/L/R/S/I), orthographic toggle.
Input (Freeview-like): 2D — left-click/drag sets cursor; wheel = slice ±1 (⌘/Ctrl+wheel = zoom); right-drag = window/level
on the top volume layer; middle/space-drag = pan; arrows nudge cursor; PgUp/PgDn slice. 3D — left orbit, right pan,
wheel dolly, double-click = pick (sets cursor to hit point). Keys: `r` reset view, `1..6` presets, `c` toggle crosshair,
`x` cycle layout, `o` orthographic. Cut plane: sliders (normal preset + free normal + offset) and a draggable gizmo.

### 7.6 Colormaps and LUTs
Continuous: gray, viridis, plasma, inferno, magma, cividis, turbo, jet, hot, cool, bone, coolwarm, bwr (diverging,
centred at 0 when `symmetric`), freesurfer-heat, plus user-loadable `.json` (array of RGB stops).
Label LUTs: FreeSurfer `FreeSurferColorLUT.txt`, SimNIBS `*_LUT.txt` (`#No. Label Name: R G B A`), ITK-SNAP label
description, and a generic `id r g b [a] [name]` fallback; auto-associate a LUT file named `<volume>_LUT.txt` or
`<volume>.txt` next to the volume; default to a deterministic glasbey-like palette otherwise.

## 8. App (Electron) — UX contract
* Dark theme, three regions: **left** layer panel (ordered list, visibility eye, opacity slider, per-kind property
  editor), **centre** view grid, **right/bottom** info panel (cursor RAS + per-layer voxel index / value / label name /
  element id / tag / field values), **top** toolbar (Open, layout, radiological toggle, screenshot, save/load scene),
  **status bar** (fps, frame ms, GPU memory estimate, last load time).
* Open: menu / ⌘O / drag-and-drop / CLI args (`tetravox file1.nii.gz mesh.msh`). File associations registered by the installer.
* Screenshot: PNG of one view or the whole grid at 1×/2×/4× DPR. Scene save/load: `*.tetravox.json` (ViewSpec).
* Everything the UI can do must be reachable from `engine` API alone (the UI is a thin client; no logic in React).

|---|---|

cross-check against reference values (e.g. node counts, field means from SimNIBS; NIfTI values vs nibabel via
`scripts/gen-fixtures.py`). Rendering has Playwright screenshot tests with pixel assertions at known positions.

## 10. Conventions
* TypeScript strict; ESLint + Prettier; no `any` in public APIs. Rust: `clippy -D warnings`, `rustfmt`.
* Commit messages: conventional commits (`feat(engine): …`). **Do not add `Co-Authored-By` trailers.**
* Every feature lands with tests and, for rendering, a screenshot under `packages/engine/test/golden/`.
* Keep dependencies minimal; justify each new one in `docs/DECISIONS.md`.
