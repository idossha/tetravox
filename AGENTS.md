# Working on Tetravox (for humans and agents)

Read `docs/ARCHITECTURE.md` first — it is the contract, and v2 is the current one. `docs/ROADMAP.md` says what is
in flight. `docs/DECISIONS.md` is append-only.

## Commands
- `pnpm install` · `pnpm wasm` (builds `crates/tvx-wasm` → `packages/wasm/pkg`) · `pnpm build` ·
  `pnpm test` (cargo test + vitest) · `pnpm e2e` (Playwright) · `pnpm dev` (Electron dev) · `pnpm package`
- Rust only: `cargo test --workspace`, `cargo clippy --workspace -- -D warnings`, `cargo bench -p <crate>`
- `pnpm wasm` is a prerequisite of `build` / `test` / `typecheck`. Never typecheck against a missing `pkg/`.
- pnpm 10 skips dependency build scripts: the root `package.json` carries
  `"pnpm": { "onlyBuiltDependencies": ["esbuild", "electron"] }`. Electron downloads its binary on **first
  launch**, not on install — run `pnpm exec electron --version` once before `pnpm e2e` on a cold machine.
- `pnpm package` builds **this platform's** artefacts only. Linux artefacts come from CI (§12.1) or
  `docker run electronuserland/builder`.

| `Simulations/Thalamus/TI/niftis/Thalamus_TI_subject_TI_max.nii.gz` | 256×256×208 | float32 (16) | 1.0 / 0.0 | 2 / 2 | −1 | 0 … 3.152071 |

Two traps encoded above:

* **T1 is float32, not int16, and its max is exactly 65535.0** — which is why R16F is not the default scalar
  format (half-float's largest finite value is 65504, so it becomes `+Inf`). The int16 volumes are the
  `label_prep/*_upsampled.nii.gz` pair at 512×512×416.
* **`labeling.nii.gz` is a float32 label volume** with 57 integral unique values. An `is_label` heuristic that
  requires an integer dtype misclassifies the atlas the app is meant to browse.
* `scl_slope` is **not** NaN on disk in any of these. Reading `nib.load(p).header` reports NaN because
  `Nifti1Image.from_file_map` calls `set_slope_inter(None, None)` after handing scaling to the array proxy. Read
  the raw 348-byte header (as `scripts/refvalues/nifti_refvalues.py` does) if you need the on-disk values. The
  NaN guard in §6.1 stays, but only the synthetic fixture exercises it.

## Rules

1. **Rendering is verified by numbers first, pictures second** (§11). Every rendering feature ships an
   *analytic* pixel assertion — expected RGBA computed from first principles on a synthetic fixture via
   `expectPixel(view, x, y, rgba, tol)` — **plus** a golden PNG for regression. Goldens are captured only under
   headless Chromium/SwiftShader at a fixed canvas size, DPR 1, `aa:'off'`, with `@playwright/test` pinned;
   compared at `maxDiffPixelRatio ≤ 0.002`, `threshold 0.15`; `ubuntu-24.04` is the golden authority.
   Regenerating a golden requires a commit body stating what changed visually. Do not "verify" a rendering
   change by looking at a PNG and declaring it fine.
2. Every parser/geometry function ships synthetic tests **plus** a real-data test gated by `TETRAVOX_TESTDATA`,
   asserting the numbers in this file.
3. **Disjoint ownership**: one agent per crate/package. Shared files (workspace `Cargo.toml`, root
   `package.json`) are pre-populated by the scaffold; only append.
4. **Frozen interfaces** (§12.3): `packages/protocol/src/index.ts`, `packages/engine/src/scene/types.ts`,
   `packages/engine/src/api.ts`, `packages/wasm/src/index.ts`, and every §6 Rust signature. Changing any of them
   requires editing `docs/ARCHITECTURE.md` in the **same commit**.
5. **Lockfiles are frozen after Phase 0.** `pnpm-lock.yaml` and `Cargo.lock` are never merged: on conflict take
   `main`'s version and re-run `pnpm install` / `cargo check --workspace` to regenerate. Phase-1 agents may not
   add a dependency without coordinating through the integrator, and any new dependency needs a line in
   `docs/DECISIONS.md`. Worktree branches rebase on `main` before merge.
6. Conventional commits, **no `Co-Authored-By` trailers**. Commit on your own branch in your own git worktree
   (`git worktree add ../tetravox-wt-<name> -b feat/<name>`); never rewrite `main`.
7. **Never block the UI thread with parsing or geometry.** De-indexing, normal generation and any vertex-buffer
   expansion count as geometry: they happen in the dataset's worker and arrive as transferables. The engine never
   builds a vertex buffer element-by-element, and raw file bytes never touch the UI thread or IPC (§5).
8. **No `rayon`, no wasm threads, no nightly Rust.** Parallelism is worker-per-dataset.
